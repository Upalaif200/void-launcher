# Void Launcher — AGENTS.md

## Project structure

Two independent subprojects in one repo:

- **Electron launcher** (root): `main.js` (main process), `renderer.js` (renderer), `index.html`, `style.css`
- **Fabric mod** (`void-mod/`): Minecraft 1.21.11 HUD mod (keystrokes, armor, potions, crosshair)

## Commands

| Command | Works in | Description |
|---------|----------|-------------|
| `npm start` | root | Run Electron launcher |
| `npm run build` | root | Build Windows NSIS installer via electron-builder (outputs to `dist/`) |
| `.\gradlew.bat build` | `void-mod/` | Build Fabric mod JAR (`build/libs/keystrokes-1.0.0.jar`) |

## Mod build requirements

- JDK 23 required (`$env:JAVA_HOME = 'C:\Program Files\Java\jdk-23'`)
- Gradle 8.14 via wrapper, Fabric Loom 1.13.1, Mojang mappings
- On each launcher launch, the mod JAR is auto-copied from `void-mod/build/libs/` to `<gameDir>/mods/`

## Key architecture notes

- Launcher config stored in `launcher_config.json` (local) and `AppData/void-launcher/` (runtime)
- No tests, no linter, no typechecker, no CI workflows, no pre-commit hooks
- All build artifacts and runtime Minecraft data are gitignored (`.gitignore` at root)
- `main.js:93` — `createWindow()` creates a frameless, non-resizable 960×620 window with `nodeIntegration: true`
- Mod ID: `void-client`, settings key: RSHIFT, config saved to `.minecraft/config/void-client.json`
- CurseForge WebView is used for mod browsing (no API key needed)

## Config map

- `launcher_config.json` — local dev config (username, ram, skin path)
- `launcher_profiles.json` — gitignored (Minecraft runtime)
- `launcher_config.json` is also the pre-migration layout; the app migrates old format on first run (`main.js:54-83`)

## Auto-updater — version/patch system

### Versioning
- Semantic versioning: `major.minor.patch` (e.g., `1.0.6`)
- Source of truth: `"version"` field in `package.json`
- Each release MUST tag with `v{version}` (e.g., `v1.0.6`)
- The tag drives `electron-updater` detection — it compares the running app's `package.json` version against the latest GitHub Release tag

### Release workflow

```powershell
# 1. Bump version in package.json
# 2. Commit and tag
git add package.json
git commit -m "chore: bump version to X.Y.Z"
git tag vX.Y.Z
git push origin master
git push origin vX.Y.Z

# 3. Build the installer
npm run build

# 4. Create release on GitHub via gh CLI
#    NOTE: gh release create renames spaces → dots in asset names,
#    so hyphenated copies are used instead
Copy-Item "dist/Void-Launcher Setup X.Y.Z.exe" "dist/Void-Launcher-Setup-X.Y.Z.exe" -Force
Copy-Item "dist/Void-Launcher Setup X.Y.Z.exe.blockmap" "dist/Void-Launcher-Setup-X.Y.Z.exe.blockmap" -Force

gh release create vX.Y.Z --title "vX.Y.Z" --notes "description" --repo Upalaif200/void-launcher
gh release upload vX.Y.Z "dist/Void-Launcher-Setup-X.Y.Z.exe" "dist/Void-Launcher-Setup-X.Y.Z.exe.blockmap" "dist/latest.yml" --repo Upalaif200/void-launcher --clobber
```

### Required environment
- **GH_TOKEN** must be set before any `gh release` command:
  ```powershell
  $env:GH_TOKEN = 'ghp_xxx...'
  ```
  Token must be classic (scope `repo`) or fine-grained (permission `contents: write`)

### Critical: filename consistency
`electron-updater` reads `latest.yml` from the release assets. The `path:` field in `latest.yml` MUST exactly match the uploaded `.exe` asset name. Electron-builder generates `latest.yml` with hyphenated names (e.g., `Void-Launcher-Setup-X.Y.Z.exe`). When uploading via `gh`, use hyphenated filenames to match — do NOT use the original space-separated names from the build output.

### Auto-updater architecture (`main.js:110-145`)

1. `app.whenReady()` → `autoUpdater.checkForUpdates()`
2. On `update-available` → sends IPC `update-available` to renderer
3. Renderer shows an in-app notification bar with **Actualizar** / **Más tarde** buttons
4. User clicks **Actualizar** → renderer sends `start-update` IPC → main calls `autoUpdater.downloadUpdate()`
5. Progress events (`download-progress`) → forwarded to renderer as `update-progress` IPC
6. Download complete (`update-downloaded`) → renderer shows "Descarga completada. Instalando..." → sends `install-update` IPC → `autoUpdater.quitAndInstall(false, true)`
7. User clicks **Más tarde** → notification hidden, flag stored in `localStorage` (`void-update-pending`)
8. On next app launch, if flag is set → re-shows notification
9. On `update-error` → notification shows error with **Reintentar** button

### Files involved
- `main.js:110-145` — auto-updater IPC handlers and event wiring
- `renderer.js` — notification UI logic, progress bar, localStorage persistence
- `index.html` — `<div id="update-notification">` element
- `style.css` — `.update-notification`, `.update-progress-bar`, `.update-action-btn`, etc.
- `dev-app-update.yml` — update config for dev mode (`npm start`)
- `dist/win-unpacked/resources/app-update.yml` — auto-generated by electron-builder for packaged app
